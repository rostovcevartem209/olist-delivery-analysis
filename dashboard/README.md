# Отчёт Power BI

Файл отчёта — olist_delivery_analysis.pbix. Данные импортируются из PostgreSQL, база olist_delivery на 127.0.0.1:5432. Представление mart.order_delivery импортировано под именем mart order_delivery.

Меры для последовательного создания приведены в measures.dax. Вычисляемые столбцы и календарь приведены в model.dax. Активная связь Календарь[Date] → mart order_delivery[Дата покупки] имеет кратность 1 ко многим, фильтр идёт от календаря к заказам.

## Проверено в Power BI

| Показатель без фильтров | Power BI и SQL |
|---|---:|
| Всего заказов | 99441 |
| Пригодные заказы | 96470 |
| Просроченные заказы | 6534 |
| Доля просрочек | 6.77% |
| Медиана доставки, дней | 10 |
| P90 доставки, дней | 23 |
| Медианная задержка просроченных, дней | 7 |

График по месяцу покупки использует Календарь[Месяц] и меру Доля просрочек. Фильтр Период сравнения = TRUE установлен на уровне графика. Март 2018 сверён по подсказке с SQL, 7003 пригодных заказа, 1328 просрочек, 18.96%.

Сборка страниц отчёта продолжается. Снимки готовых страниц и итоговая сверка ещё предстоят.

Распределение по delay_group сверено по подписям диаграммы. Для групп «Вовремя или раньше», «1–3 дня», «4–7 дней», «8–14 дней», «15 дней и более» получены 89936, 1870, 1802, 1478 и 1384 заказа соответственно.

На странице «Обзор доставки» создан срез customer_state. При выборе SP карточки показали 40494 пригодных заказа, 1820 просрочек и 4.49%, что совпало с SQL. На скриншоте также видны пересчитанные графики и сроки доставки. Фильтр периода сравнения относится к месячному графику. Карточки и распределение задержек используют весь период в рамках выбранного штата.

После снятия выбора SP общие показатели восстановились. Названия графиков указывают период расчёта. Файл PBIX сохранён с первой страницей для промежуточной фиксации проекта. Оформление и остальные страницы ещё разрабатываются.

## Страница «Проблемные сегменты»

Созданы таблица штатов и пузырьковая диаграмма. У диаграммы ось X — пригодные заказы, ось Y — доля просрочек, размер — количество просрочек, условные обозначения — штат покупателя. Подсказка SP сверена с SQL по скриншоту, 40494 заказа, 4.49%, 1820 просрочек и медианная задержка 5 дней. Таблица показывает совпадающие значения SP, RJ, MG и общий итог 96470 заказов, 6534 просрочки, 6.77% и 7 дней медианной задержки.

Мера Объём выборки добавлена в таблицу и подсказки. По скриншоту AP сверены 67 заказов, 2 просрочки, доля 2.99%, медианная задержка 72.5 дня и отметка Менее 100 заказов. Мера медианной задержки отображается с одним десятичным знаком. Выбор AP в таблице фильтрует диаграмму.

Мера Вклад в просрочки добавлена в таблицу. Знаменатель снимает фильтр customer_state, остальные фильтры сохраняются. По скриншоту сверены SP 27.85%, RJ 22.88%, MG 7.94% и итог 100%.

Мера Накопленный вклад добавлена в таблицу. Штаты упорядочиваются по числу просрочек по убыванию, при равенстве — по коду по возрастанию. По скриншоту подтверждены SP 27.85%, RJ 50.73%, MG 58.68%, BA 64.74% и общий итог 100%. После сохранения пользователем подтверждено обновление PBIX на диске 21 ноября 2026 года.

Импортированы mart.order_seller и mart.order_category с именами mart order_seller и mart order_category. Типы столбцов проверены по Power Query. Связь продавцов по order_id подтверждена по свойствам модели, активная, многие к одному от продавцов к основной витрине, с фильтром от основной витрины к продавцам. Детальные свойства связи категорий ещё требуется сверить.

Созданы меры Заказы продавца и Просрочки продавца для пригодной подвыборки seller_count = 1. TREATAS передаёт список order_id из текущего контекста продавца в основную витрину. По скриншоту таблицы сверены общий итог 95195/6521 и лидер 4a3ca9315b744ce9f8e9374361493884 с 1673 заказами и 168 просрочками. Для таблицы подготовлен визуальный фильтр Заказы продавца > 0. На момент первого скриншота условие введено, нажатие кнопки применения ещё требуется.

Меры доли просрочек, медианной задержки и объёма выборки продавца созданы и добавлены в таблицу.
